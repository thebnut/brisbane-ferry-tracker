# @bft/ferry

BrisbaneFerry on the transit platform: Vite 8 + React 19.3 + React Router 8.4 framework mode on Cloudflare Workers
(`@cloudflare/vite-plugin`, SSR), styled with `@bft/ui`, data from the `/v1` contract (`@bft/core`). The live app at
the repo root is untouched.

```sh
pnpm --filter @bft/ferry dev            # http://localhost:5173, add ?fixtures=1 for recorded data
pnpm --filter @bft/ferry test           # unit tests (Vitest)
pnpm --filter @bft/ferry test:e2e       # Playwright smoke (builds, runs wrangler dev in fixture mode)
pnpm --filter @bft/ferry fixtures       # rebuild app/data + fixtures from a GTFS dir (default /tmp/bft-gtfs/x)
pnpm --filter @bft/ferry deploy:staging # needs `wrangler login`: bft-ferry.brisbanetransit.workers.dev
```

## Routes
- `/` two departure boards for the selected pair. Stop selector on first visit (or when "Remember selection" is
  off), dropdown headers and swap (temporary, like the legacy app), All/Express filter, "Depart from", "More
  departures" (5 → 13), details sheet (times, delay, vessel, stopping pattern from `/v1/ferry/trips`, live map), live
  ferry map. The saved pair also goes in a `bft_pair` cookie so the server renders its rows into the HTML.
- `/terminal/:slug` SSR terminal pages: same URLs, title, description, canonical, OG and JSON-LD as the legacy
  postbuild (tested against it for all 22 terminals), with live board rows and a "next departures" table in the HTML.
- `/privacy`, `/terms` prerendered (copy taken from the legacy `public/*.html` at build time). Unknown paths and
  unknown terminals: 404 with `noindex`.
- `/sitemap.xml` generated by the Worker: the same 25 URLs, order and priorities as the legacy sitemap.

## Data
- Same-origin `/v1/*` proxy in the Worker (service binding `API` to `bft-api` in staging, `API_BASE` over HTTP
  otherwise). The proxy and SSR loaders validate every response with the `@bft/core` zod schemas (a drift becomes a
  502), so the browser bundle carries only the types, not zod. A same-origin proxy also avoids CORS and lets the
  service worker cache data.
- TanStack Query polls every 15 s while visible and pauses when the tab is hidden (tested); "updated n s ago" from
  `rtSourceTimestamp`; banners for `rtState` stale/reloading/unavailable and for offline.
- Fixture mode (`?fixtures=1` when `ALLOW_FIXTURES=1`, or `FIXTURES=1` for everyone): `/__fixtures/v1/...` serves
  responses built by `@bft/core` `mergeDepartures` from a recorded weekday of real ferry stop-day files
  (`fixtures/ferry-day.json`, 525 KB, server-only) with a deterministic synthetic RT snapshot, rebased to today.
  `?rt=unavailable|stale|reloading` forces a state.
- Terminals and direct connectivity are generated from GTFS into `app/data/terminals.json` (ids, names and slugs are
  tested equal to the legacy list). Once the pipeline publishes `data/ferry/stops.json` this can move to it.

## PWA
vite-plugin-pwa 2 (generateSW): manifest, precached JS/CSS/icons (MapLibre excluded), network-first caches for pages
and `/v1/ferry` departures/trips (24 h). Offline, the last good response per pair is shown as timetable times with
"Offline · scheduled".

## Staging
Deployed to **https://bft-ferry.brisbanetransit.workers.dev** (`pnpm --filter @bft/ferry deploy:staging`, workers.dev
only, `API` service binding to `bft-api`). While `bft-api` has no ferry data (`503 no static data for mode`), the
boards show the error state; add `?fixtures=1` to see recorded data.

## Measurements (18 Oct 2026)

Lighthouse 13.5 mobile, simulated slow 4G (1.6 Mbps, 150 ms RTT, 4× CPU), 3 runs each, fixture mode.

| Where | Page | Perf | A11y | BP | SEO | TTFB | FCP | LCP | TBT | CLS |
|---|---|---|---|---|---|---|---|---|---|---|
| staging (workers.dev) | `/` | 98 | 100 | 100 | 100 | 19–22 ms | 1.8–2.0 s | 2.0 s | 0 | 0 |
| staging (workers.dev) | `/terminal/bulimba` | 98 | 100 | 100 | 100 | 20–37 ms | 1.8 s | 2.0 s | 0 | 0 |
| local `wrangler dev` | `/` | 95–97 | 100 | 100 | 100 | | 2.0–2.1 s | 2.3–2.6 s | 0 | 0 |

- LCP element: the header lockup (WebP 17 KB at 360 w, was a 76 KB PNG). Departure rows are in the SSR HTML
  (home 8.9 KB gz, terminal page 10.9 KB gz) and paint with FCP.
- FCP is bounded by the render-blocking CSS after the HTML. Inlining critical CSS at the edge would save a round trip.
- The 1.5 s target is for a real mid-range Android; Lighthouse's simulated slow 4G is harsher.

**Worker CPU (Workers Free allows 10 ms per request)**, from `wrangler tail` on staging, warm isolates:

| Request | CPU |
|---|---|
| `/` or `/terminal/:slug` SSR with full boards (fixture data) | 11–16 ms |
| same with no rows (API 503, error states) | 4–10 ms |
| `/__fixtures/v1/…/departures` | 1 ms |
| first request in a new isolate (module init) | 30–60 ms |

SSR of the full boards is **over the Free 10 ms budget**; Cloudflare tolerated it in these runs, but it isn't safe.
Options: the $5 plan (not approved), an in-isolate HTML micro-cache for cookie-less pages, or a lighter SSR (render
fewer rows server-side). `@bft/core` `serviceDayStartEpoch` was memoised in this PR: it built a `TZDate` per stop
event and made a merge ~10× slower (3 ms → 0.3 ms for Bulimba; the edge API benefits too).

First-load JS (gzip -9, home): **about 140 KB**, over the 90 KB budget.

| Chunk | gz |
|---|---|
| react-dom client (`entry.client`) | 65.5 KB |
| react-router (`jsx-runtime` + `errorBoundaries` chunks) | 39.9 KB |
| TanStack Query + app data layer (`queries`) | 11.1 KB |
| board UI (`FerryBoards`, `Chrome`, `root`, `format`, route) | 20.6 KB |
| small shared chunks | 2.8 KB |

React 19 DOM plus React Router 8 alone are about 105 KB gz, so 90 KB is not reachable with the ADR-0005 stack. App
code is about 35 KB. zod was moved server-side (−27 KB). Lazy: stop selector (Ark UI, 34 KB), map (MapLibre,
279 KB + 10 KB CSS). JS does not block LCP (no TBT). The Worker bundle is 387 KB gz (MapLibre stubbed out of SSR).

Offline reload was verified in desktop Chrome with the server stopped (page and rows served by the service worker).
Playwright checks the cached page and precache instead, because its Chromium offline emulation and request routing
bypass the service worker.
